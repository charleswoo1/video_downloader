# Security Policy

## Supported versions

Security fixes are targeted at the latest published release.

## Reporting a security issue

Do **not** include cookies, browser databases, access tokens, credentials, session data, private URLs, or other secrets in a public GitHub issue.

If GitHub shows a private vulnerability-reporting option under the repository's **Security** tab, use that channel. If no private reporting option is available, open a minimal public issue that contains only a high-level description and asks the maintainer to establish a private channel. Do not publish exploit details or secret material in that issue.

For ordinary download failures that do not involve a security vulnerability, use the Bug Report issue template.

## Sensitive local data

The application may read browser cookies when the user explicitly enables cookie-based access. Cookie material should remain local and must never be attached to Issues, Pull Requests, Actions logs, or other public repository content.
